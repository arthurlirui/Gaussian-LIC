\subsection{Design Rationale and Topology Selection}

We evaluated three topologies against the requirements of cooperative Gaussian
SLAM: (i) fully centralized (1 server, $N$ clients), (ii) fully decentralized
(full-mesh P2P), and (iii) hierarchical hybrid. Table~\ref{tab:topology} 
summarizes the analysis.

  \end{tabular}

\subsection{Three Degradation Modes}

The architecture supports three operating modes that preserve functionality
under worsening connectivity:

\begin{enumerate}
  \item \textbf{Mode A --- Full cooperation (Tier-0 + Tier-1 + Tier-2).} All
    three tiers active. The Tier-0 server performs cross-cluster loop closure,
    global PGO, and authoritative map versioning. This mode provides highest
    consistency and is the target for infrastructure-supported deployments.

  \item \textbf{Mode B --- Intra-cluster P2P (Tier-1 + Tier-2, no Tier-0).}
    When the edge server is absent or unreachable, cluster heads communicate
    directly (P2P) and each maintains its own merged map. Cross-cluster
    consistency is achieved through opportunistic head-to-head submap exchanges.
    This is the target for ad-hoc, infrastructure-less deployments.

  \item \textbf{Mode C --- Autonomous single-node (Tier-2 only).} When a node
    loses all peers (total partition), it falls back to unmodified
    Gaussian-LIC2~\cite{lang2026gaussian2}, buffering submaps locally. On
    reconnect, buffered submaps flush in chronological order. Map quality
    after a 30~s outage remains within 5\% of the connected baseline.
\end{enumerate}

\subsection{Cluster-Head Election Protocol}

\label{sec:election}

Cluster heads are elected through a stable, deterministic protocol that resists
thrashing under marginal link quality.

\paragraph{Score function.} Each node $i$ computes:
\begin{equation}
  \text{score}(i) = w_c \cdot \tau_{\text{compute}}(i) + w_q \cdot \sqrt{\bar{Q}^{(i)}} + w_s \cdot (N_c^{(i)} + N_l^{(i)}),
  \label{eq:score}
\end{equation}
where $\tau_{\text{compute}}(i) \in \{1, 2, 3, 4\}$ maps to {Orin, 4090, A100,
> A100}, $\bar{Q}^{(i)}$ is the EWMA link quality (Section~\ref{sec:channel}),
and weights default to $w_c=0.5$, $w_q=0.4$, $w_s=0.1$. The $\sqrt{\bar{Q}}$
term dampens the effect of transient link quality changes.

\paragraph{Election state machine.} Each node tracks head state as one of 
{\footnotesize CANDIDATE, FOLLOWER, HEAD}:

\begin{algorithm}[t]
\caption{Cluster-head election protocol (per node).}
\label{alg:election}
\begin{algorithmic}[1]
\State \textbf{Upon} HEARTBEAT from current head $h$:
\State \quad reset election timer $T_e \gets 3$~s.
\State \textbf{Upon} $T_e$ expiry (head timeout):
\State \quad broadcast ELECTION(self.score).
\State \quad collect ELECTION msgs from peers for $T_{\text{collect}}=500$~ms.
\State \quad \textbf{if} self.score > all peers' scores:
\State \qquad promote self to HEAD; broadcast HELLO\_HEAD.
\State \quad \textbf{else}:
\State \qquad set $h \gets \arg\max_j \text{score}(j)$; transition to FOLLOWER.
\State \textbf{Upon} receiving HELLO\_HEAD from $h'$ with higher score:
\State \quad demote to FOLLOWER; accept $h'$ as new head.
\end{algorithmic}
\end{algorithm}

\paragraph{Stability mechanisms.} Three dampeners prevent election storms:
(1) \emph{Hysteresis threshold $\delta_h=0.05$}: a FOLLOWER only triggers
election if its score exceeds the head's by $>\delta_h \cdot \text{score}(\text{head})$.
(2) \emph{Election back-off}: after losing an election, a node waits
$T_{\text{backoff}} = 2$~s before campaigning again. (3) \emph{Head lease}: an
elected head holds the role for a minimum $T_{\text{lease}}=1$~s regardless of
new arrivals.

\subsection{Multi-Hop Submap Routing}

When a submap's destination (cluster head, or Tier-0 server) is not directly
reachable by the publishing node, the submap is routed through intermediate
nodes. This is common in ad-hoc deployments where not all nodes have line-of-sight.

\paragraph{Routing table.} Each node maintains a distance-vector routing table
populated by HELLO and HEARTBEAT gossip. Entry: $(\text{dst}, \text{next\_hop},
\text{hop\_count}, \text{path\_PDR})$. Updates are piggybacked on HEARTBEAT.

\paragraph{Store-and-forward.} If the next hop is temporarily unreachable (link
loss), a submap is buffered at the forwarding node for up to $T_{\text{buffer}}=30$~s,
retried every 1~s, and evicted after timeout. The originating node receives a
NACK with retry\_info.

\paragraph{Submap dedup.} Submap IDs are globally unique
($\text{node\_id} \ll 32 \mid \text{seq}$). Intermediate nodes maintain a
Bloom filter of recently forwarded submap IDs to prevent routing loops.
