# iOS Port Refactor: MetalSplatter Rendering + MLX Swift Training

## Problem Summary

The current iOS port at `ios/` has three showstoppers:
1. **Build broken** — `Package.swift` depends on `../third_party/msplat` which doesn't exist (msplat is Python-only, can't be a Swift dependency)
2. **Rendering targets iOS 27+** — uses `RealityKit GaussianSplatComponent` which is an unreleased API; won't compile on any shipping Xcode
3. **Training is fake** — `OnDeviceTrainer.swift` returns simulated loss values; never imports or calls any real training library

## Solution: Two Open-Source Replacements

### Rendering → MetalSplatter (MIT, already in `third_party/MetalSplatter/`)
- Mature Swift/Metal 3DGS renderer, iOS 18+, supports PLY/SPZ/.splat, SH0–SH3, stereo
- Clean public API: `SplatRenderer`, `SplatChunk`, `AutodetectSceneReader`
- Already cloned as a git submodule — just needs to be wired into `Package.swift`
- Integration pattern is well-documented in `MetalSplatter/SampleApp/Scene/MetalKitSceneRenderer.swift`

### Training → MLX Swift (Apache 2.0, Apple's official ML framework)
- iOS 17+, Metal-backed array framework with automatic differentiation (`MLX.grad`), optimizers (`MLXOptimizers.Adam`), and NN building blocks
- We'll implement a simplified differentiable Gaussian splatting rasterizer using MLX array operations: project Gaussians → 2D, compute per-pixel alpha blending via broadcasting, L1+SSIM loss, autograd backward, Adam step
- Works on-device for small scenes (a few thousand Gaussians, downsampled images) — appropriate for iPhone capture-and-train workflow

### 3. Rendering Layer — Rewrite for MetalSplatter

**`SplatRealityView.swift`** — Replace `ARView`/RealityKit with `MTKView` + `SplatRenderer`
- Change from `UIViewRepresentable` wrapping `ARView` to wrapping `MTKView` with an `MTKViewDelegate` that drives `SplatRenderer.render(...)`

**`SplatSceneManager.swift`** — Replace RealityKit entity management with SplatRenderer lifecycle

- `loadScene(from:)` now: `AutodetectSceneReader(url).readAll()` → `[SplatPoint]` → `SplatChunk(device:from:)` → `renderer.addChunk(chunk)`

**`PLYLoader.swift`** — Remove or simplify

**`MetalHelpers.swift`** — Keep, minor cleanup

### 4. Training Layer — Rewrite with MLX Swift

**`OnDeviceTrainer.swift`** — Replace simulated loop with real MLX training
- `import MLX`, `import MLXOptimizers`, `import MLXRandom`
- **Training context** (`MsplatContext` → `MLXTrainingContext`): holds `MLXArray` buffers for positions, SH coefficients, scales (log), rotations (quaternion), opacity (logit), plus Adam optimizer state
- **`createMLXContext`**: Convert `[GaussianSplat]` to `MLXArray` tensors; create `Adam` optimizer with per-parameter learning rates
- **`performOptimizationStep`**: 
  1. Pick random training frame
  2. Forward pass: project Gaussians to 2D (MLX matrix ops), compute 2D covariance, evaluate per-pixel alpha blending (broadcasting — feasible at low res like 128×96)
  3. Loss: L1 + 0.2 × (1 - SSIM) against ground-truth image
  4. Backward: `MLX.grad` or `MLX.valueAndGrad` for automatic differentiation
  5. Adam optimizer step
- **`densify`**: Real gradient-based clone/split — compute per-Gaussian position-gradient magnitude, clone under-reconstructed areas, split large Gaussians, prune low-opacity
- **Export**: Convert MLX arrays back to `[GaussianSplat]` → write standard 3DGS PLY (keep existing `exportPLY` logic)
- Keep the same public API (`train(datasetURL:iterations:maxGaussians:onProgress:onComplete:)`) so `TrainingProgressView.swift` needs no changes

**New file: `Sources/Training/MLXRasterizer.swift`** (~300 lines)
- Differentiable 3DGS forward renderer using MLX array operations
- `projectGaussians(positions, rotations, scales, viewMatrix, intrinsics) → (means2D, cov2D, depths)`
- `rasterize(means2D, cov2D, colors, opacities, sortedIndices, width, height) → renderedImage`
- `computeSSIM(predicted, target) -> MLXArray` — 11×11 window SSIM
- Sorted by depth (argsort on MLXArray), alpha-blend front-to-back

## Risk Assessment
- **MLX rasterizer**: The simplified per-pixel broadcasting approach works for small scenes (≤5K Gaussians, 128×96 res) but won't scale to millions. This is acceptable for on-device iPhone training where we cap Gaussians at 50K and downsample aggressively. A future optimization could add custom Metal compute shaders.
- **MetalSplatter integration**: Low risk — the API is stable, well-documented, and the SampleApp provides a working integration reference. The `MetalKitSceneRenderer.swift` pattern can be followed closely.
- **MLX Swift dependency**: Adds a ~50MB framework. This is standard for on-device ML apps and MLX is Apple's official framework.
