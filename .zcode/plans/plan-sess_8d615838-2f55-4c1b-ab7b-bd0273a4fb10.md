# iOS 移植重构计划 — Gaussian-LIC → RealityKit + msplat

## 诊断总结

现有 `ios/` 代码（17 个 Swift 文件，~2678 行）**无法编译**。问题分三类：

| 类别 | 状态 | 详情 |
|------|------|------|
| **传感器采集**（ARKit RGB/LiDAR/Depth/IMU → 磁盘） | ✅ 完整可用 | `ARKitSensorSource`、`IMURecorder`、`FrameRecorder`、`CaptureSession` 代码质量高，无 stub |
| **渲染** | ❌ 全部写错 | `SplatRenderView` 调用不存在的 `updateViewports`/`render(to:with:renderPassDescriptor:clearColour:)`；`SplatSceneManager` 用错误的 `SplatPLYSceneReader(url:)` 标签、不存在的 `read(maxSplatCount:progress:)`、`add(splatScene)` |
| **UI / 训练** | ❌ 完全缺失 | `CaptureView`、`RenderView`、`TrainingProgressView`、`DeviceCapabilityView`、`TrainingRecord` 全部不存在；无任何训练代码 |

### 构建配置错误
- `Package.swift`: iOS 17 + tools 5.9，但 MetalSplatter 要求 iOS 18 + tools 6.1 + Swift 6
- 声明了 `Tests` 目录的测试目标但目录不存在
- `.bgra8Unorm` 应为 `.bgra8Unorm_srgb`

### 其他 Bug
- `DepthVisualization.visualizeConfidence`: defer 括号错误，吞掉函数体
- `ARSplatOverlay` + `ARKitSensorSource` 各创建独立 ARSession，运行时冲突

---

## 决策

根据用户选择：
1. **渲染**：弃用 MetalSplatter，改用 Apple 原生 `GaussianSplatComponent`（RealityKit 内置，iOS 27+）
2. **训练**：添加 `msplat`（Apache 2.0）子模块做端上 Metal GS 训练 + 保留离线导出

**2.2 重写 `SplatSceneManager.swift`**
- 用 RealityKit `GaussianSplatComponent` + `GaussianSplatResource` 替代 MetalSplatter
- 加载路径：读取 PLY → 解析为 position/scale/rotation/opacity/SH GPU buffers → `GaussianSplatResource.BufferResource` → `GaussianSplatResource` → `GaussianSplatComponent` → `Entity`
- 保留 `LoadedScene` 结构（url, name, splatCount, transform, visible）
- 保留 `maxGaussians` 内存安全上限（Apple 限制 ~200K splats，我们按设备分级 150K-500K）

**2.3 新建 `SplatRealityView.swift`**（替代 SplatRenderView + ARSplatOverlay）
- `RealityView` (SwiftUI) 内容：
  - 将 `GaussianSplatComponent` entity 添加到 RealityKit scene
  - 自由查看模式：手势控制 orbit camera（用 `CameraComponent` 或 gesture 修改 entity transform）
  - AR 实时模式：从 `CaptureSession` 的 `ARKitSensorSource` 获取 ARFrame camera matrices → 设置 RealityKit camera transform
  - 单一 ARSession（复用 `ARKitSensorSource` 的 session，不再创建第二个）
- 用 `UIViewRepresentable` 包装 `ARView`（RealityKit），如果 `RealityView` SwiftUI API 不够灵活则用 `ARView` 直接控制

**2.4 新建 `PLYLoader.swift`**（在 `ios/Sources/Utilities/`）
- 解析标准 3DGS PLY 二进制格式（x,y,z, f_dc_0-2, f_rest_0-44, opacity, scale_0-2, rot_0-3）
- 反交错为独立的 `LowLevelBuffer`：position(float3)、scale(float3)、rotation(float4)、opacity(float)、SH(float)
- 清理 NaN/Inf（RealityKit 拒绝非有限值）
- 返回 `GaussianSplatResource.BufferResource`
- 也可以直接用 Apple 示例中的 `readGaussianSplatFile` + `deinterleaveGaussianSplatData` 模式

**2.5 修复 `MetalHelpers.swift`**
- 移除 MetalSplatter 相关注释
- 保留 simd 矩阵扩展（`.translation`、`.upperLeft3x3`、`.fx/.fy/.cx/.cy`）仍被其他模块使用
- 移除 `makeDepthTexture`/`makeColorTexture` 等仅 MetalSplatter 用的函数（RealityKit 自管理 render targets）

### 阶段 4：实现端上训练（msplat 集成）

**4.1 新建 `ios/Sources/Training/OnDeviceTrainer.swift`**
- 包装 msplat Metal 训练引擎（通过 Swift C interop 或 Swift Package wrapper）
- 输入：数据集路径（images/ + trajectory.txt + intrinsics.txt）
- 流程：加载图片 → LiDAR 反投影初始化点云 → msplat 前向渲染 → L1 + SSIM loss → 反向传播 → Adam 优化 → densification（受内存上限约束）→ 导出 PLY

- Gaussian 上限：按设备 RAM 分级（6GB→100K, 8GB→200K, 12GB+→300K），到达上限时停止 densification

## 关键技术依据

- **GaussianSplatComponent API** (iOS 27+)：`GaussianSplatResource(bufferResource)` → `GaussianSplatComponent(resource)` → `Entity`，自动处理 SH/scale/opacity 激活函数。Apple 限制 ~200K splats/scene（足够 iPhone 渲染）。
- **msplat** (github.com/rayanht/msplat, Apache 2.0)：Metal 后端的 3DGS 训练引擎。`apple_spatial_capture` Flutter 插件已验证 iPhone 上可行：500 迭代 / ~4 分钟 / 内存受控。
- **PocketGS** (arXiv 2601.17354)：学术证明 iPhone 15 上 4 分钟可完成端上 3DGS 训练（500 迭代, LPIPS 0.108），为我们的方案提供可行性依据。
- **复用现有传感器层**：`ARKitSensorSource`、`IMURecorder`、`FrameRecorder`、`CaptureSession` 代码质量高，无需改动。
- **复用现有数据模型**：`SensorFrame`、`CameraIntrinsics`、`GaussianSplat`、`DeviceProfile` 保持不变。
