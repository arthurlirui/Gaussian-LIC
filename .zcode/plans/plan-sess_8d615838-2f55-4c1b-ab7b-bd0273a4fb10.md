# Gaussian-LIC iOS 移植计划

## 概述

将 Gaussian-LIC 的核心实现移植到 iOS 平台，用 RealityKit + MetalSplatter 作为渲染基础，通过 ARKit 调用 iPhone 14 Pro–18 Pro 的 RGB、LiDAR、Depth、IMU 传感器，实现实时采集 + 静态高斯泼溅场景训练。

**架构决策（基于研究）：**
- **渲染**：MTKView + MetalSplatter（已在仓库 `third_party/` 中），RealityKit 负责 AR 会话管理和场景锚定
- **训练**：混合方案 — Phase 1 实现 iPhone 采集→离线训练→回传 PLY 渲染；Phase 2 添加端上轻量 Metal compute 训练
- **传感器**：ARKit `ARWorldTrackingConfiguration` 提供 RGB、LiDAR depth、IMU/VIO，对应 `win_lic` 的 `ISensorSource` 接口

## 实现阶段

### Phase 1: 项目骨架 + 传感器采集（核心）

**1.1 Xcode 项目 + SPM 依赖**
- 创建 iOS App 项目（SwiftUI, iOS 17.0+ 最低版本）
- 通过 Swift Package Manager 引用本地 `third_party/MetalSplatter`（相对路径 `../third_party/MetalSplatter`）
- 配置 Info.plist：`NSCameraUsageDescription`、`NSMotionUsageDescription`、`UISupportedInterfaceOrientations`

**1.2 ARKitSensorSource.swift — ARKit 传感器封装**
- 对应 `win_lic/sensors/isensor_source.h` 的 `ISensorSource` 接口
- `ARWorldTrackingConfiguration` 配置：
  - `frameSemantics = [.sceneDepth, .smoothedSceneDepth]`（LiDAR 深度）
  - `sceneReconstruction = .mesh`（可选，用于场景理解）
- 每帧从 `ARFrame` 提取：
  - **RGB**：`frame.capturedImage`（CVPixelBuffer → CIImage → CGImage，或直接传 Metal texture）
  - **LiDAR Depth**：`frame.sceneDepth.depthMap`（密集深度图，单位米）
  - **Depth Confidence**：`frame.sceneDepth.confidenceMap`
  - **Pose**：`frame.camera.transform`（simd_float4x4，camera-to-world）
  - **IMU**：ARKit 内部 VIO 已融合到 pose；额外用 `CMMotionManager` 采集原始 accel/gyro
  - **Intrinsics**：`frame.camera.intrinsics`（3x3 矩阵，像素单位）
- 输出 `SensorFrame` 结构体（Swift 版 `AlignedFrame`）：
  ```swift
  struct SensorFrame {
      let timestamp: Double
      let image: CVPixelBuffer          // YUV or BGRA
      let depthMap: CVPixelBuffer       // Float32, metres
      let confidenceMap: CVPixelBuffer?  // UInt8
      let cameraTransform: simd_float4x4 // camera-to-world
      let intrinsics: simd_float3x3
      let imuData: IMUSample?            // accel + gyro
      let frameIndex: Int
      var isKeyframe: Bool
  }
  ```

**1.3 IMURecorder.swift — 原始 IMU 数据**
- `CMMotionManager` 以 100Hz 采集 `deviceMotion.userAcceleration` + `deviceMotion.rotationRate`
- 时间戳与 ARFrame 对齐（使用 `CFAbsoluteTimeGetCurrent` 与 ARKit timestamp 的偏移校准）
- 缓冲到环形队列，`ARKitSensorSource` 每帧快照

**1.4 DeviceProfile.swift — 设备能力检测**
- 检测 iPhone 14 Pro / 15 Pro / 16 Pro / 17 Pro / 18 Pro 的具体型号
- 检测 LiDAR 可用性：`ARWorldTrackingConfiguration.supportsFrameSemantics(.sceneDepth)`
- 检测 TrueDepth 前置（可选用于面部扫描）
- 返回设备能力描述：LiDAR 范围（~5m）、深度分辨率（256×192）、RGB 分辨率（1920×1440）

### Phase 2: 数据记录 + 离线训练桥接

**2.1 FrameRecorder.swift — 帧记录器**
- 将 `SensorFrame` 写入 App Documents 目录：
  - `images/000001.jpg`（RGB，JPEG 压缩）
  - `depth/000001.exr` 或 `000001.bin`（Float32 原始深度图）
  - `depth_conf/000001.bin`（UInt8 置信度图）
  - `trajectory.txt`（TUM 格式：timestamp tx ty tz qx qy qz qw）
  - `imu.csv`（timestamp, ax, ay, az, gx, gy, gz）
  - `intrinsics.txt`（fx, fy, cx, cy, width, height）
- 关键帧选择策略：每 N 帧（默认 5）或运动超过阈值时标记关键帧
- 磁盘空间监控：超过 2GB 时警告

**2.2 DatasetExporter.swift — 导出为 win_lic 兼容格式**
- 生成的目录结构完全兼容 `win_lic/sensors/dataset_reader.h` 的 `DatasetReader`
- 这样可以直接用现有 `winlic` 可执行文件在 Mac/CUDA 服务器上训练
- 导出后可通过 AirDrop / iCloud / 局域网 HTTP 传输到训练服务器

**2.3 OffDeviceTrainingBridge.swift — 训练桥接**
- 简单的 HTTP 客户端：POST 采集数据到 Mac 上运行的训练服务
- 轮询训练进度（PSNR、迭代次数）
- 训练完成后下载 `point_cloud.ply`
- 替代方案：手动 AirDrop + 手动运行 winlic 命令行

### Phase 3: 渲染管线（MetalSplatter 集成）

**3.1 SplatRenderView.swift — MTKView 包装**
- `UIViewRepresentable` 封装 `MTKView` + `MTKViewDelegate`
- 初始化 `SplatRenderer`（来自 MetalSplatter）
- 每帧更新 `Uniforms`：
  - `projectionMatrix`：ARKit `frame.camera.projectionMatrix` 或手动透视矩阵
  - `viewMatrix`：ARKit `frame.camera.viewMatrix(for:)` 或手势控制的虚拟相机
  - `cameraPosition`：从 viewMatrix 逆矩阵提取
  - `focalX/focalY/tanHalfFovX/tanHalfFovY`：从 projectionMatrix 计算
- 两种相机模式：
  - **AR Live 模式**：直接用 ARKit 的相机矩阵，splats 叠加在真实世界上
  - **Free View 模式**：手势控制虚拟相机轨道/缩放，纯 PLY 浏览

**3.2 SplatSceneManager.swift — 场景管理**
- 加载 PLY 文件（通过 MetalSplatter 的 `SplatPLYSceneReader`）
- 支持多个场景同时加载，通过 chunk enable/disable 切换
- 场景变换：位置/旋转/缩放（用于 AR 模式下对齐到现实空间）
- 内存管理：`max_gaussians` 限制（参照 Jetson 配置，iPhone 设为 200K-500K）

**3.3 ARSplatOverlay.swift — AR 模式**
- `ARView`（RealityKit）作为背景层，提供 AR 会话和相机画面
- MTKView 透明叠加在 ARView 上方，渲染 splats
- 使用 ARKit pose 同步：ARView 的 `session.delegate` 获取 `ARFrame`，传递 camera transform 给 MTKView 的 SplatRenderer
- 用户可拖拽放置 splat 场景的原点到 AR 空间中的某个平面位置

### Phase 4: UI + 交互

**4.1 CaptureView.swift — 采集界面**
- 全屏 AR 相机预览
- 实时深度图彩色化叠加（可切换显示/隐藏）
- 采集控制：开始/暂停/停止
- 帧计数 + 已录制时间 + 估算磁盘占用
- 关键帧标记可视化
- 设备温度监控（`ProcessInfo.thermalState`，达到 `.serious` 时警告）

**4.2 RenderView.swift — 渲染界面**
- MTKView 全屏渲染
- 手势：
  - 单指拖拽：轨道旋转
  - 双指捏合：缩放
  - 双指拖拽：平移
  - 双击：重置视角
- 加载 PLY 文件（Files App / AirDrop / App 内文档目录）
- AR 模式切换按钮

**4.3 TrainingProgressView.swift — 训练进度**
- 显示当前训练状态：上传中 / 训练中 / 下载中 / 完成
- 训练指标：迭代次数、PSNR、SSIM、高斯数量
- 历史训练记录列表

### Phase 5: 端上轻量训练（Phase 2，后续迭代）

**5.1 OnDeviceTrainer.swift — Metal compute 训练**
- 参考 PocketGS（arXiv 2601.17354）：500 迭代、~4 分钟、iPhone 15
- 用 Metal compute shaders 实现精简版训练循环：
  - 前向渲染（复用 MetalSplatter 的 fragment shader 输出）
  - L1 + D-SSIM loss 计算（Metal compute kernel）
  - 反向传播（自定义 Metal kernel，alpha compositing 的梯度散射）
  - 内存优化 Adam 优化器
- 初始化策略：用 ARKit LiDAR 点云作为几何先验（对应 `win_lic` 的 `initialize()`）
- 限制：≤100K 高斯，≤500 迭代，分辨率降至 512×384

**5.2 Metal 训练着色器**
- `training/forward_render.metal` — 前向渲染 + 缓存中间值
- `training/loss.metal` — L1 + SSIM loss kernel
- `training/backward.metal` — 梯度反传 kernel
- `training/adam.metal` — 内存优化 Adam 步骤

## 关键技术映射表

| win_lic (C++/CUDA) | iOS (Swift/Metal) | 备注 |
|---|---|---|
| `ISensorSource` | `ARKitSensorSource` | ARKit 替代 Orbbec/dataset reader |
| `AlignedFrame` | `SensorFrame` | CVPixelBuffer 替代 cv::Mat |
| `CameraPose` (Eigen quaternion) | `simd_float4x4` | ARKit 原生提供 |
| CUDA rasterizer forward | MetalSplatter `SingleStageRenderPath.metal` | SH/covariance/blend 已 1:1 移植 |
| LibTorch autograd + Adam | Metal compute kernels (Phase 5) / off-device (Phase 1-4) | |
| TensorRT SPNet depth completion | ARKit dense LiDAR depth | 无需补全 |
| OpenCV SGBM stereo | 不需要 | iPhone 只有单 RGB + LiDAR |
| `DepthFusion` (LiDAR+iToF+stereo) | 直接用 ARKit depth | 单源密集深度 |
| PLY export/load | MetalSplatter `SplatPLYSceneReader` | 标准 3DGS PLY 格式 |
| `max_gaussians` cap (Jetson) | `max_gaussians` (iPhone, 200K-500K) | 内存安全 |

## 实施顺序

1. **Phase 1**（骨架 + 传感器）：创建 Xcode 项目，实现 `ARKitSensorSource` + `IMURecorder` + `DeviceProfile` + `CaptureView`，能在 iPhone 上实时显示 RGB + 深度预览
2. **Phase 2**（记录 + 导出）：实现 `FrameRecorder` + `DatasetExporter`，能录制数据并导出为 win_lic 兼容格式
3. **Phase 3**（渲染）：实现 `SplatRenderView` + `SplatSceneManager`，能加载 PLY 并渲染
4. **Phase 4**（UI 完善）：`RenderView` 手势、AR 模式、训练进度 UI
5. **Phase 5**（端上训练，后续迭代）：Metal compute 训练管线

每个 Phase 完成后可独立测试和验证。Phase 1-4 完成后即可实现完整的"iPhone 采集 → 离线训练 → iPhone 渲染"工作流。
